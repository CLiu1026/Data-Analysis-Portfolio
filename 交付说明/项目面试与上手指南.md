# 数据分析项目上手与面试指南

## 简历如何使用

`国内投递/数据分析CV.docx` 为可编辑的一页中文简历；原始运筹简历保留。新项目日期为 2026.10，标注公开数据实践；没有把历史数据年份写成项目制作年份，也没有虚构企业上线、营销活动或增长收益。

这次由 AI 帮助搭建了项目，不等于你已经具备全部 SQL 能力。投递前请完成下面的独立操作，按实际掌握情况调整技能表述。面试若问到工具辅助，应如实说明；不要说成此前独立完成或公司项目。

原有路径项目数字沿用你的运筹简历，没有原始代码可再次验证。因此保留“模拟场景”“按学习偏好得分”等限制，不把 100% 写成满意度、真实业务提升或预测准确率。AI 产品经理简历与运筹简历的奥克兰起始月分别为 2026.07 和 2026.09，本版使用你指定的运筹简历中的 2026.09，请按真实入学记录核实。

尚未填写 GPA、明确专业名称、到岗时间、每周天数、实习时长与城市/远程安排，因为指定文件没有这些信息。它们尤其影响你在奥克兰学习期间的国内实习可行性；明确后可加在联系方式下。

## 上手顺序

1. 打开看板，先回答三个问题：总经营金额和客户金额为什么不同？为什么 12 月不算环比？为什么大额客户还要核对取消金额？
2. 双击项目中的 `重新运行.command`，查看自己的重跑结果与 `summary.json` 是否一致。原始 XLSX 已在本地，正常情况下不需要重新下载。
3. 阅读 `01_schema.sql`，画出“交易行 → 订单 → 客户”的粒度关系。订单视图一行一个 InvoiceNo，不能把订单商品行数当作购买频次。
4. 逐段阅读 `02`、`03`、`04`，不要一次背完整语句。先分别解释 GROUP BY、JOIN、CTE，再解释 LAG、NTILE、ROW_NUMBER 和累计 SUM。
5. 修改 RFM 的截止日或一个分层阈值，预测结果如何变化后再运行。保留一份修改记录；改变后勿继续沿用原简历数字。
6. 独立写出“每月订单数与客单价”的 SQL，再与项目脚本比较。最后不看文件讲解项目五分钟。

建议先掌握这个完整项目，不必为了简历数量拆成两个近似的电商项目。已有推荐系统保留数理与实验优势，新项目补上业务指标及 SQL 证据。

## 三分钟项目讲解参考

“我选择真实公开电商交易数据，想回答经营走势、客户贡献和复购三个问题。原始数据有约 54 万条明细，我先检查重复、取消和缺失客户编号。经营统计保留匿名订单，但客户分层和复购只使用可识别客户。随后把明细汇总到订单粒度，用 SQL 的 CTE 和窗口函数计算月度指标、RFM、客户贡献累计占比和同期群复购。

在正向交易口径下，前约 20% 的客户贡献 74.68% 的可识别客户金额；完整可观测同期群的加权次月复购率是 23.65%。分析中发现最大的两笔购买随后取消，所以我额外做了客户粒度的取消金额核对；12 月只有九天数据，也不能与完整月份直接比较。项目最终输出数据库、SQL、离线看板和报告，SQL 结果用 Pandas 独立对账。分层运营和召回只是建议，没有实际业务收益数据。”

使用这一讲解前，务必完成实际复跑与理解，并根据自己真实做过的内容修改主语与分工。可以说明项目使用 AI 辅助、你负责的复核和改动，不能照背为过去已经独立做过的经历。

## 面试追问

| 问题 | 回答重点 |
| --- | --- |
| 为什么 SQL 很重要，不直接全部用 Pandas？ | SQL 展示数据库粒度、关联和聚合口径；Pandas 用于导入与独立核对。不是因为本地 54 万行一定只能用数据库。 |
| JOIN 为什么可能放大金额？ | 两边关联键不唯一形成多对多；先按客户/订单汇总，核查唯一性后关联。08 中取消记录先按客户汇总。 |
| CTE 和子查询有什么区别？ | 本项目用 CTE 把分析拆成可阅读阶段，不声称 CTE 必然更快。 |
| COUNT 和 COUNT DISTINCT 区别？ | 明细 COUNT 是交易行；COUNT DISTINCT InvoiceNo 是订单数；匿名 CustomerID 不计入去重客户数。 |
| 为什么 RFM 的 F 不用 Quantity？ | Quantity 是商品数量；购买频次应按独立订单计数。 |
| NTILE 同值怎么处理？ | 可能将相同频次分到不同分位，按编号排序保证复现；如业务要求同值同分，可改用明确业务阈值或秩方法。 |
| 怎么算 23.65%？ | 对 M1 已完整观测的群，次月购买人数 940 / 首购群人数 3,974；排除未完整观测月份。 |
| 0 与 NULL 为什么不同？ | 0 是完整观测后无人复购；NULL 是观察窗还不完整，不代表客户流失。 |
| 重复行一定应该删除吗？ | 没有唯一明细 ID，不能保证；本版采用去重候选分析，同时保留原数据和 0.23% 金额差异。 |
| 为什么不能说退货率或净收入？ | C 前缀表示取消，不保证实物退货；没有原单匹配、利润和会计状态信息。 |
| 最大局限是什么？ | 历史英国礼品/批发数据、匿名客户、左截断与尾端不完整；毛额客户价值会被取消影响。 |
| 你的分析让复购提高多少？ | 没有执行触达或对照实验，不能声称提高。可以解释下一步如何验证。 |

## SQL 小练习

先不看答案，尝试完成：

1. 返回每个月正向订单数、总金额与客单价；禁止用商品明细 COUNT 作为订单数。
2. 计算每位可识别客户购买次数、距末次购买天数与金额；再查看谁的正向金额高但带符号金额接近零。
3. 对首购群计算 M1 复购；显式区分没有购买与没有完整观察。
4. 将“前 20% 客户金额贡献”改成前 10%，解释向上取整与分母。
5. 在取消记录关联前后检查行数与总金额，找出为何要先按客户聚合。
